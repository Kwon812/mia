# 계획 — 관측 계층과 스킬 추출

2026-08-09 작성. 근거는 `HANDOFF-attach.md` 의 측정이다.

## 왜 이 순서인가

**관측은 되돌아가서 못 한다.** 오늘 안 적은 클릭은 영영 없다. 붙이는 순간부터
시계가 돈다 — 후보가 보이기까지 3~5일이 필요하다(실측: 20세션·5일에서 2회
반복이 1일·2일·4일째 도달, 3회는 미도달).

**갈래 교정은 기다릴 게 없다.** 이미 있는 경험 29건에 바로 작동한다.

그래서 관측을 먼저 켜고, **쌓이는 동안** 교정을 만든다. 반대로 하면 교정을
만드는 동안 관측이 논다.

두 갈래는 파일이 겹치지 않는다 — 관측은 `apps/extension`, 교정은
`apps/web` 과 `packages/db`.

## 0단계 · 관측 계층 (지금, 대기 없음)

갈고리는 이미 박혀 있다. `apps/extension/src/content.ts:115`

```js
document.addEventListener('click', () => clicks++, { passive: true });
document.addEventListener('keydown', () => keys++, { passive: true });
```

**듣고 있는데 세기만 한다.** 무엇을 눌렀는지 안 적는다.

### 0-1 조작을 기록한다

`clicks++` → 무엇을 눌렀는지 남긴다. 첫 결정이 **기록 입도**다.

| 안 | 남기는 것 | 절차 추출 | 크기 |
|---|---|---|---|
| A 최소 | 태그·역할·보이는 텍스트 | 대부분 가능 | 작다 |
| **B 권장** | A + 안정 셀렉터(id/data-\*/aria) | 재실행까지 가능 | 중간 |
| C 최대 | B + 입력값 전체 | 값까지 재현 | 크다 |

**B 를 고른다.** A 는 "무엇을 눌렀나"만 알아 재실행이 안 되고, C 는 입력값이
곧 내용이라 크기와 성격이 크게 달라진다. B 는 입력을 **길이와 종류**로만
남긴다(`text 12자`, `date`) — 절차의 뼈대에는 충분하다.

### 0-2 종결 조작을 표시한다

절차인지 헤맨 건지 가르는 가장 강한 신호다. 무언가를 **바꾸는** 조작:
submit · save · download · deploy · 파일 생성 · 폼 전송.

이게 나중에 **후조건**이 된다 (4단계). 지금 안 남기면 나중에 못 만든다.

### 0-3 압축을 통과시킨다

`apps/extension/src/sw.ts`

```js
const RAW_RETENTION_MS = 3 * 24 * 60 * 60 * 1000;
```

로컬 원본은 사흘이면 지워진다. 절차는 **몇 주에 걸친 반복**을 비교해야 하므로
조작은 raw 가 아니라 **`compressed_log` 에 실려 서버로** 가야 한다.

지금 압축은 60초 미만 구간을 접는다 — 조작 상세가 거기서 뭉개지면 안 된다.
구간은 접되 조작 열은 보존하는 규칙을 만든다.

**크기**: 지금 세션당 1,972B · DB 전체 13MB. 조작을 넣으면 세션당 10~30KB 로
10~15배. 하루 4세션(실측) 기준 월 3~5MB. Supabase 무료 500MB 에 몇 년 치다.

### 검증
- 확장 재적재 후 실제 브라우징 1일치로 `compressed_log` 크기·형태 확인
- 사흘 뒤 raw 가 지워져도 조작이 서버에 남아 있는지 확인

## 1단계 · 갈래 교정 (0단계와 병행)

측정: 사람이 고치면 F1 54.3 → 60~88. 40세션에 5~15번, 하루 한두 번꼴.

### 1-1 스키마 한 줄

`packages/db/src/schema.ts:526`

```
check('corrections_field_check', field in ('outcome','category','is_first_time'))
                                                              ↑ 'thread' 없음
```

`CORRECTION_FIELDS` 에 `thread` 추가 + 마이그레이션.

### 1-2 지도에서 고치기 — 연산 넷

측정이 말하는 것: 정밀 43% / 재현 74% / 분할 80%. **옮기기 하나로는 못 고친다.**

| 연산 | 왜 | 무게 |
|---|---|---|
| 경험 옮기기 | 오염 (정밀 43%) | `thread_id` 한 칸 |
| **갈래 병합** | 분산 (재현 74%) — 빠뜨리면 안 된다 | `thread_id` 일괄 |
| 갈래 이름 고치기 | 이름이 활동이지 대상이 아니다 | `title` 한 칸 |
| 세션 재처리 | 경험 자체가 섞임 (분할 80%) | 경험 삭제 + `processed_at=null` |

앞의 셋은 가볍다. 네 번째는 `corrections.experience_id` 가 cascade 라
**교정이 딸려 날아간다** — 되살릴지 정해야 한다.

정할 규칙(HANDOFF 에 목록 있음): 갈래가 0건이 되면 / 첫 경험이 오판이면 /
끝난 갈래로 옮기면 / 기억이 근거를 잃으면 / 되돌리기.

### 1-3 대조축으로 적는다

측정: 제목 쌍은 규칙 12~13줄이 전부 1회. 대조축은 8줄에 4~5회까지 쌓인다.
날것 F1 62.6 (기준선 54.3).

```
✗  베타 스토어 배포 → 알파 대시보드 (1회)         일회용
✓  같은 도메인이어도 갈래가 다르다 → db.example.com (5회)   재사용
```

교정 순간에 **잘못 붙었던 갈래와 겹쳤던 것**을 뽑는다 — 겹쳤는데도 사람이
갈랐으니 그 겹침은 근거가 아니었다는 뜻이다.

### 검증
- `probe-fixture.mts --axis` 가 이미 이 형식을 만든다. 실제 구현이 같은
  줄을 내는지 대조
- 실데이터 19세션 재구축으로 갈래 수 확인

## 2단계 · 스킬 후보 (0단계 3~5일 뒤)

### 2-1 경계는 반복이 준다

자르고 나서 맞추는 게 아니라 **겹치는 구간이 곧 절차**다.

```
월: ... 메일 → [Supabase → 테이블 → 필터 → 내보내기] → 유튜브
금: ... 슬랙 → [Supabase → 테이블 → 필터 → 내보내기] → 잠
                └── 공통 부분열 = 절차 ──┘
```

오늘 갈래에서 못 쓴 방법이다(경험은 한 번뿐이라 비교 대상이 없다).
절차는 반복이 전제라 쓸 수 있다.

### 2-2 절차인가 헤맨 건가 — 전부 코드, LLM 없음

| 신호 | 절차 | 헤맴 |
|---|---|---|
| 다음 단계 엔트로피 | 낮다 | 높다 |
| 실행 간 차이 | 값만 다르다 | 뼈대가 다르다 |
| 방향 | 한 방향 | 왔다갔다 |
| 종결 조작 | 있다 | 없다 |

도메인 수준에서도 이미 갈린다(실측): `dashboard.render.com` 1.37bit /
최빈 60% vs `www.google.com` 2.00bit / 최빈 25%.

`localhost → supabase.com → localhost` 가 7세션에 나왔지만 **진동이라
쓸모없다** — 아무것도 안 바뀌고 확인만 오갔다. 종결 조작이 이걸 걸러낸다.

**실행 간에 변한 것이 곧 매개변수다.** 오늘 사람이 손으로 만든 대조축을
반복이 공짜로 만든다.

### 2-3 스킬 탭 — 후보와 승인

```
"이 흐름을 두 번 하셨어요:
   Google Docs → 로컬 → snailbook 관리자
 절차로 만들까요?"     [예, 이름은 ___]  [아니오]
```

3회를 기다리는 이유는 **자동으로 확신하기 위해서**다. 사람이 답하면 1회
줄고, 무엇보다 틀린 후보가 걸러진다.

**문턱은 낮게.** 틀린 제안은 「아니오」 한 번이고, 놓친 절차는 아예 안 보인다.
그리고 「아니오」도 데이터다 — 오늘 대조축과 똑같이 거절이 다음 판정의 축이 된다.

**값어치 판단은 뽑아낼 수 없다.** 귀찮음은 관측되지 않는다. 코드는 순위만
매긴다(단계 수 × 빈도 × 기계성). 모델이 좋아지면 없어질 한계가 아니라
구조적으로 그렇다 — 오늘 30pt 를 잃은 것과 같은 이유다.

## 3단계 · SKILL.md 생성

승인된 후보에만 LLM 을 쓴다. 후보 추리기는 전부 코드라 호출이 적다.

스크립트가 아니라 SKILL.md 인 이유: 버튼 위치가 바뀌면 스크립트는 죽지만
SKILL.md 는 에이전트가 읽고 맞춘다.

**후조건을 반드시 같이 적는다.**

```
후조건: 다운로드 폴더에 experiences-*.csv 가 생겼다
        그리고 행 수가 0 이 아니다
```

0-2 의 종결 조작에서 뽑는다. **지금 안 넣으면 4단계에서 전부 다시 써야 한다.**

## 4단계 · 게이트 (나중)

`leesj10147/automation` 의 구조에서 가져올 부분.

| | 하는 일 |
|---|---|
| Replay | 다시 돌려 후조건을 만족하나 |
| Shadow | 사람이 하는 옆에서 조용히 돌려 대조 (실행 안 함) |
| Verifier | 후조건 독립 확인 |

게이트가 사주는 것은 하나다 — **안 보고 돌릴 수 있느냐.** 지켜봐야 하는
자동화는 직접 하는 것보다 조금 편한 정도다.

저 저장소에서 **안 가져올 것**: Rust 크레이트, Linux AT-SPI, Windows UI
Automation, 네이티브 호스트 설치기. 여러 플랫폼을 덮는 비용이고 크롬 하나면 된다.

(그 저장소에서 실제로 자동화된 업무의 실례는 못 찾았다 — `packages/` 는
전부 `*-lab`, 즉 실험대다. 저자도 "아직 범용 자율 시스템이 아니다"라고 적어뒀다.)

## 하지 않는 것

- **4시 배치** — 필요는 하나 1단계가 같은 문제를 덮는다. 나중에 "손 안 대도
  어느 정도 되게" 하는 보강으로 얹는다. 구조는 안 바뀐다.
- **프롬프트 문구 손질** — 끝났다. 가설 6개 기각, 판단력에 여지 11%.
  기각 목록은 `HANDOFF-attach.md`.
- **데스크톱 관측** — 크롬 밖은 범위 밖.

## 범위가 달라지는 점

조작을 남기면 관측이 "어디 있었나"에서 "무엇을 눌렀나"로 넘어간다. B 안은
입력을 길이·종류로만 남겨 내용은 안 담지만, 클릭한 요소의 **보이는 텍스트**는
남는다. 저장 위치는 지금과 같다(로컬 3일 + Supabase).

## 먼저 정할 것

1. 기록 입도 — A / **B(권장)** / C
2. 세션 재처리 시 딸려 날아가는 교정을 되살릴지
3. 스킬 후보를 2회에서 물을지 3회를 기다릴지 (권장: 2회)
